## Findings

### F-1 — HIGH: `setThemeUserId` not memoized → language race condition in signed-in session

**File**: `src/lib/theme.ts` (ThemeProvider body) + `src/modules/mod-home/AppShell.tsx` (lines ~190–198)  
**Branch-audit reviewer.**

`setThemeUserId` is declared as a plain function inside `ThemeProvider`'s render body, so every ThemeProvider re-render creates a new function object. AppShell's `useEffect` lists it as a dependency:

```ts
useEffect(() => {
  setThemeUserId(session.user.id);
  void loadLanguageForUser(session.user.id);
  return () => {
    setThemeUserId(null);
    void applySignedOutLanguage();   // ← async, fire-and-forget
  };
}, [session.user.id, setThemeUserId]);   // ← setThemeUserId changes every render
```

When the user changes their theme (or the OS toggles dark mode), ThemeProvider re-renders → new `setThemeUserId` reference → effect cleanup fires `void applySignedOutLanguage()` → effect setup fires `void loadLanguageForUser()`. Both are async AsyncStorage reads racing against each other. Whichever resolves last wins. A signed-in user whose account language is `en` but whose device language is `zh-TW` can see the UI language flip to `zh-TW` after a theme change.

**Fix (engineer-mod-home):** Wrap `setThemeUserId` in `useCallback` with an empty dep array in ThemeProvider:

```ts
const setThemeUserId = useCallback((newUserId: string | null): void => {
  setUserId(newUserId);
}, []);
```

### F-2 — MEDIUM: Save failure blocks sign-out entirely

**File**: `src/modules/mod-localization-theme/screens/SettingsScreen.tsx` (~lines 194–200) + `src/lib/devicePrefs.ts` (save helpers)  
**Branch-audit reviewer.**

`saveDeviceLanguage` and `saveDeviceTheme` are awaited inside the same `try` block as `signOut()`. Both save helpers rethrow on AsyncStorage failure. If either throws (device storage full, AsyncStorage corruption), `signOut()` is never called and the user sees "Failed to save language preference." while remaining signed in. This is disproportionate: preference persistence is non-critical and must never gate sign-out, especially on a shared device.

**Fix (engineer-mod-localization-theme):** Wrap saves in an inner best-effort try/catch:

```ts
try {
  try {
    await saveDeviceLanguage(selectedLanguage);
    await saveDeviceTheme(selectedOverride);
  } catch (prefErr) {
    console.error('[handleLogout] device pref save failed (non-fatal):', prefErr);
  }
  await signOut();
} catch (err) { ... }
```

### F-3 — MEDIUM (structural): `copyGoogleAvatarToBucket` is media-sync logic inside the auth module

**File**: `src/modules/mod-auth-profile/auth-service.ts` (lines ~408–496)  
**Code-quality reviewer.**

`auth-service.ts` declares its contract: "All Supabase Auth calls go through here." `copyGoogleAvatarToBucket` does exactly one auth call (`getSession`) and then runs 8 sequential IO steps: DB read, CDN-domain guard, `fetch`, `arrayBuffer`, `Uint8Array`, content-type sniffing, `supabase.storage.upload`, and DB `update`. This is feature-specific media orchestration, not auth plumbing.

**Recommendation for Tech Lead:** Extract to a dedicated `avatarSync.ts` file. Thread `userId` as a parameter to eliminate the redundant `getSession()` call. Apply the same parameter threading to `fillDisplayNameIfEmpty`. Route to engineer-mod-auth-profile.

### F-4 — LOW: Sequential saves in `handleLogout` should be parallel

**File**: `src/modules/mod-localization-theme/screens/SettingsScreen.tsx` (~lines 197–200)  
**Code-quality reviewer.**

`saveDeviceLanguage` and `saveDeviceTheme` are independent AsyncStorage writes run sequentially. Replace with `Promise.all([...])` — a one-line change with no behavioral risk.

### F-5 — LOW: `applySignedOutLanguage` name leaks auth state concept into the i18n module

**File**: `src/lib/i18n.ts` (line ~122)  
**Code-quality reviewer.**

The function is session-agnostic (read stored language → fall back to device → call changeLanguage) but its name implies auth awareness. Renaming to `restoreDeviceLanguage()` makes it reusable for any reset flow and removes the session coupling. One call site in `AppShell.tsx` needs updating.

### F-6 — LOW: Initial theme double-load — device theme briefly precedes user theme

**File**: `src/lib/theme.ts` (ThemeProvider init)  
**Branch-audit reviewer — informational.**

ThemeProvider initializes `userId` to `null`, immediately starting `loadSignedOutTheme()`. AppShell shortly calls `setThemeUserId(session.user.id)`, starting `loadSavedOverride()`. On slow storage, the device theme could flash briefly before the user theme is applied. Low-probability in practice. No action required now; note if theme flash is reported post-launch.

### F-7 — LOW: `copyGoogleAvatarToBucket` — no download size cap

**File**: `src/modules/mod-auth-profile/auth-service.ts` (~line 458)  
**Branch-audit reviewer — informational.**

`await response.arrayBuffer()` runs without checking `Content-Length` first. A pathologically large Google photo would exhaust the JS heap. Google profile photos are universally small in practice. A defensive `content-length` pre-flight check would eliminate the theoretical OOM risk. Can be bundled with the F-3 extraction.
